  - `placeFeatures` 现在按原版方式为每个装饰器组独立重设种子，消除跨特征相关性。
  - `AquaticGenerator` 只在区块含海洋/河流/沼泽/海滩群系且目标列上方有水时才放置水下盘。
  - 树木改用传入的 3x3 `WorldGenLevel`，树冠可写入相邻区块，避免硬边界。
  - 已通过 `mvn -o compile -DskipTests` 编译。
- 修复海面仍呈规则条纹/斑块的问题（见下）。

- 修复海面仍呈规则条纹/斑块的问题：
  - 根因：`AquaticGenerator.placeDisk` 原版应仅做 top-down 连续目标层替换（一层薄盘），但实现成了圆柱体体积填充，且 target 包含 sand/gravel，导致磁盘互相转换、斑块过厚。
  - 重写 `placeDisk`：按原版 DiskFeature 语义，从 `cy+halfHeight` 向下扫描到 `cy-halfHeight`，只替换顶部连续的目标方块层；sand 目标仅限 dirt/grass_block，gravel 同，clay 目标 dirt/clay；sand 在下方为空气时替换为 sandstone。
  - `placeDisks` 改用传入的 3x3 `WorldGenLevel`，磁盘可自然延伸到相邻区块，避免切块硬边。
  - 已通过 `mvn -o compile -DskipTests` 编译。

## 协议 774 包 ID 校准与生存回归 (SurvivalBot 13/13)

### 权威包表提取方法（可复用）
- 源文件：`mapping/cfr-source/net/minecraft/network/protocol/game/GameProtocols.java`
- 用正则抓 `addPacket(...)` 的出现顺序即为包 ID 顺序。
- CLIENTBOUND 必须 +1（`withBundlePacket` 把 BUNDLE 塞在 0x00）；SERVERBOUND 不加偏移。
- 关键值（已核实）：
  - SERVERBOUND: 0x06 CHAT_COMMAND / 0x0B CLIENT_COMMAND / 0x0E COMMAND_SUGGESTION /
    0x10 CONTAINER_BUTTON_CLICK / 0x11 CONTAINER_CLICK / 0x12 CONTAINER_CLOSE / 0x19 INTERACT /
    0x1B KEEP_ALIVE（不是 0x1A，0x1A 是 JIGSAW_GENERATE）/ 0x1D~0x20 MOVE_PLAYER_* /
    0x28 PLAYER_ACTION / 0x29 PLAYER_COMMAND / 0x34 SET_CARRIED_ITEM(short) /
    0x37 SET_CREATIVE_MODE_SLOT / 0x3C SWING / 0x3F USE_ITEM_ON / 0x40 USE_ITEM
  - CLIENTBOUND(+1): 0x01 ADD_ENTITY / 0x04 BLOCK_CHANGED_ACK / 0x08 BLOCK_UPDATE /
    0x12 CONTAINER_SET_CONTENT / 0x14 CONTAINER_SET_SLOT / 0x23 ENTITY_POSITION_SYNC /
    0x29 HURT_ANIMATION / 0x2B KEEP_ALIVE / 0x30 LOGIN / 0x42 PLAYER_COMBAT_KILL /
    0x44 PLAYER_INFO_UPDATE / 0x46 PLAYER_POSITION / 0x4B REMOVE_ENTITIES / 0x50 RESPAWN /
    0x51 ROTATE_HEAD / 0x65 SET_EXPERIENCE / 0x66 SET_HEALTH

### 服务端修复（NetworkHandler.java）
1. 打怪逻辑从错误的 0x2E(RECIPE_BOOK_SEEN_RECIPE) 迁到 0x19 INTERACT；抽出 `attackMob(int)` 方法，
   0x19 里玩家未命中时 `if (!hitPlayer) attackMob(targetEid);` 回落到生物/末影龙部件。
2. use_item 0x44(越界) → 0x40；容器点击 0x10 → 0x11。
3. 移动包 onGround 改为读 flags 位 `(b & 1) != 0`（bit1 是 horizontalCollision），
   补齐 0x20 MOVE_PLAYER_STATUS_ONLY。
4. giveItem 槽位顺序 Bug：原来从槽 9 开始填（主背包优先），与原版不符。
   原版 Inventory 索引 0-8 就是快捷栏，所以协议槽必须先 36-44 再 9-35。
   已加 `PICKUP_SLOT_ORDER` 常量并改用 `getMaxStackSize(itemId)`。ItemEntity 拾取也走同一路径。
5. 放置方块重复扣物品 Bug：`use_item_on` 末尾有两段一模一样的 `if (gameMode == 0)` 扣减代码，
   生存模式放 1 个方块扣 2 个物品。已删掉第二段。

### 回归机器人（tools/SurvivalBot.java）
- 攻击包 0x2E→0x19；keep-alive 回包 0x1A→0x1B；REMOVE_ENTITIES 监听 0x47→0x4B。
- 开局补 `/gamemode survival`（默认是创造，创造不掉落物品也不被怪攻击 → 之前多项误判 FAIL）。
- 加 `ensureAlive()`：被怪打死后自动重生，否则服务端 isDead 过滤会丢弃后续所有包（日志静默，极难排查）。
- 断言改为精确坐标校验：正确解码 BLOCK_UPDATE 的 26/12/26 位有符号坐标；
  ADD_ENTITY 解析 x/y/z 后按距离挑出脚下召唤的怪（服务器同时有自然刷怪，取"最后一个"会选错目标）。
- 生命值判定改用峰值 healthMax（周围怪会持续掉血，瞬时值不稳定）。
- 结果：13/13 PASS。

### 环境备忘
- 启动服务器必须用完整依赖类路径：`java -cp "target/classes;$(cat cp.txt)" com.yanrong.server.Main`
  （只写 `libs/*` 会 NoClassDefFoundError: io/netty/channel/EventLoopGroup）。
- 编译走 PowerShell：`mvn -o compile -DskipTests -q`（bash 下 mvn 会 ClassNotFoundException plexus Launcher）。
- PowerShell 里 `java -Dfile.encoding=UTF-8` 会被解析错，需加引号或改用 bash。
- bash 里 `rm` 被安全守卫拦截会导致整条命令失败，启动脚本别带 rm。
