## 第二轮修复（用户真实客户端联调反馈）
用户实机测试报 3 类 bug，本轮定位并修复：

1. **末影之眼/所有实体出生即客户端崩溃（根因）**：`PacketBuffer.writeVelocity` 写的是自定义变长编码（1 字节或 7+ 字节），但 ADD_ENTITY(0x01) 与 Entity Velocity(0x63 击退) 的速度字段协议规定是**恰好 3 个 short（6 字节）**。字节数不一致 → 包错位 → 客户端崩溃。
   - 修复：重写为 `writeShort(round(v*8000.0))` ×3 并钳制到 short 范围。
   - 位置：`../../src/main/java/com/CharunCore/server/network/protocol/PacketBuffer.java`。

2. **只生成一半地形 / 传送回卸载区块不发包（根因）**：`handleMove` 在异步生成 0x2C 区块**之前**就发出 `chunk_batch_finished`(0x0B)，客户端收到批次结束即丢弃后续 0x2C → 半地形。
   - 修复：把 0x0B 与卸载逻辑移入 `allOf(...).thenAccept` 回调、在所有 0x2C 之后发送；`sendInitialChunks` 与 `handleMove` 半径统一为 `VIEW_DISTANCE`(=12，原写死 8)。
   - 位置：`NetworkHandler.java` handleMove / sendInitialChunks。

3. **`/locate stronghold` 定位与实际不符**：`generateStronghold` 有地表高度门槛会跳过生成，但 `/locate`(findNearest) 与末影之眼无此门槛 → 指到的格子可能没要塞。
   - 修复：去掉 `generateStronghold` 的 `surface<=SEA_LEVEL-2 || surface>=220` 提前 return，使生成与定位一致。
   - 位置：`../../src/main/java/com/CharunCore/server/worldgen/structure/StructureManager.java`。
   - 注：stronghold 仍用均匀 48 格网（非原版环形），属真实性差异，不影响定位正确性。
